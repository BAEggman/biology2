### 2.3 보안 · 권한
- **토큰 · 비밀번호를 넣지도 쓰지도 않는다**(사용자가 허락해도). GitHub 에 올리는 일은 사용자가 `~/Downloads/push_b2.command` 로 직접 한다. 토큰을 `.git/config` · 명령줄 · 환경변수 · `push_b2.sh` · 문서 어디에도 두지 않는다. `push_b2.sh` 를 고칠 때마다 `grep -cE "github_pat_[A-Za-z0-9_]{20,}" push_b2.sh` = 0 을 확인하고, 로그는 `sed -E 's/github_pat_[A-Za-z0-9_]+/***/g'` 로 가려서 본다. 사용자가 정한 것: 「pat 토큰은 별 상관없어, 계속 커밋해야해」 — 토큰을 없애라고 권하지 않는다.
- 컨테이너에서 `git push` 는 하지 않는다(막혀 있다). GitHub 읽기는 자격 증명 없이 공개 읽기만(`git -c credential.helper= fetch/ls-remote https://github.com/BAEggman/biology2.git`).
- CAPTCHA 는 풀지도 돌아가지도 않는다. 약관 · 동의 · 로그인 창이 뜨면 멈추고 사용자에게 알린다.
- 사용자의 메일 주소 · GPT 감사 원문은 공개 저장소에 넣지 않는다. 노트 · 프로젝트 문서에도 토큰 · 메일 주소를 쓰지 않는다.
- 그림: 아는 캐릭터 · 실존 인물을 닮게 그리지 않는다 · 아기에게 정장 · 넥타이를 입히지 않는다 · 글자 · 숫자를 넣지 않는다.
- 에이전트: 독자는 sonnet(Agent 도구 · general-purpose). Workflow 도구는 쓰지 않는다(사용자가 켠 적 없다). 로컬 Cron 도구는 쓰지 않는다.
- 커밋 끝줄(귀속)은 **그 세션의 system-reminder 가 주는 두 줄**을 쓴다(`tools/kit/tcommit.sh` 에 환경변수로).

## 3. 일하는 법

### 3.1 Sketchy 원칙 — 과마다 스스로 묻는 여덟 가지
1. 한 무대(세계) · **한 사건**인가 — 누가 누구에게 무엇을 하는가를 한 문장으로 말할 수 있는가.
2. 물건 하나 = 사실 하나인가. 같은 물건이 덱의 다른 곳에서 다른 뜻으로 쓰이지 않았는가(`_심볼예약` · `lesson/symbols.html`).
3. 물건이 사실을 부르는 고리(소리 · 모양 · 하는 짓)가 있는가 — 인터폰 = 인터페론 · 깍둑썰기 기계 = Dicer.
4. 기묘한가(bizarreness) — 과장 · 엉뚱한 짝 · 익살. 얌전한 도해가 되지 않았는가.
5. 개수 · 자리 · 방향 · 빛깔이 뜻이면 정확한가(그린 뒤 내가 직접 셈).
6. 글자 · 숫자 없이 읽히는가.
7. obj 는 **보이는 것만** 적었는가(뜻은 fact · hook) · 그림에 없는 것을 글에 쓰지 않았는가.
8. 글을 보지 않은 독자의 첫인상이 이야기로 나오는가.

### 3.2 과 하나의 길
`tools/kit/README.md` §1 ~ §4 의 열 걸음 그대로: 카드 읽기 → 사건 짓기(설계서) → 출연진 그림 → S1 장면 통째(Gemini 카본 높음) → 구역 편집 → PIL → 다시 만드는 길 → 글(JSON) → 일치 검사 → 예약 → 빌드 · 테스트 → 셈 → 커밋 · 번들 · 문서 · 보고.

### 3.3 과 하나를 끝냈다고 말하는 조건
- [ ] 설계서 `tools/prompts/<ID>_설계.md` — 사건 · 정거장 표 · 그리는 길 · 일치 검사 회차표 · 배운 것 · 남은 것
- [ ] 그림 `lesson/img/<ID>.webp`(2048×1144) — 글자 · 숫자 · 아는 캐릭터 없음 · 개수는 내가 셈

### 3.4 자주 틀린 것(인계서 ㉛ ~ ㊽ 에서)
- 단추 · 배지가 올 가슴 · 조끼 앞을 처음부터 비운다(팔 · 손 · 굽은 허리가 가린다). 배지는 몸통 윗부분(발치 = 「땅에 떠 있다」).
- Gemini 는 「NO buttons」를 어기고 점을 찍는다 · 글자 비슷한 것을 넣는다 → 지우고 센다. 금빛 점을 줄지어 찍으면 무엇이든 단추로 센다.
- 같은 물건 둘이 맞닿으면 하나로 읽힌다. 사물에 선을 달면 생물이 된다. 「자기」 표지는 성 안 모두에게(일부만 달면 안 단 쪽이 남).
- **동작은 사건 자체를 그린다**(찢는 문어) — PIL 표시(금 · 조각)로 때우지 않는다. **인과의 끈을 그림 안에**(두루마리가 기계로 들어감).
- 물줄기 · 줄 · 길은 끝이 방향을 정한다 · 밑동은 다른 물과 뗀다 · 물 끝 곁에 불을 두지 않는다.
- Gemini 는 더하는 편집은 틀을 지키고 옮기는 편집은 틀을 다시 짠다 → 옮기기 · 지우기 · 개수는 PIL.
- 빨간 리본 = 「건넴」 예약이라 끈은 갈색으로. 빨간 옷은 붉은 배지를 묻는다.
- 정도를 말하는 글(「가장자리까지」 「코앞」 「똑같은」)은 독자마다 다르게 본다 → 뜻만 단정하고 정도는 느슨하게.

## 5. B — 고칠 것(카드)

### 5.1 원칙
- 카드는 `index.html` 의 `<script id="CARDS">`(5,688장)이 원본이고 `srs_v8.html` 에 같은 것이 있다. 손으로 고치지 않고 **패치 파일**로 고친다.
- **근거의 차례**: ① 기출 원문과 해설(프로젝트의 `BM편입생물기출1230_상/하` · `한의편_*`) ② 기본서(프로젝트의 단원 문서) ③ 캠벨 요약(`campbell_ch*.docx`) · 일반 교재. `project_search` 로 그 대목을 찾아 읽고 고친다.
- 기출 · 기본서에 **그렇게 적혀 있는** 것은 답을 지우지 않는다 — 답(`a`)은 두고 덧말(`n`)에 「기본서는 … / 일반 교재는 …」을 적거나, 물음을 기본서 문장에 맞게 고친다. 사실과 어긋나는 대목은 `n` 에 ⚠ 로 밝힌다.
- 화면에 뜨는 칸을 모두 고친다: `q` · `a` 와 함께 `it`(목록) · `cz`(빈칸) · `n`(덧말) · 자식 카드(`<id>#n`). `node tools/kit/cardfull.js <id>` 로 먼저 다 본다.
- 카드를 **지우거나 합치지 않는다**(복습 기록이 걸려 있다) — 중복은 §5.4 처럼.
- 고친 카드를 말하는 과의 글도 함께 고친다(아래 표의 「함께」).

### 5.2 하는 법
```sh
node tools/kit/cardfull.js IM-021 E0-181 …                        # 지금 글(모든 칸)
# tools/plan/2026-11-14/patch_cards.json 을 쓴다:
#   {"ops":[{lesson,stop,field,old,new}], "cards":[{"card":"E0-181","field":"a","old":"…","new":"…","from":"기출 전남대 465"}, {"card":"E0-181","field":"it","old":[…],"new":[…]}]}
```

- `old` 는 지금 글과 글자 하나까지 같아야 한다(다르면 아무것도 쓰지 않는다). 목록 칸(`it`)은 `old` · `new` 를 목록으로, 없던 칸(`n`)을 새로 달 때는 `"old": null`. 본보기: `tools/audit/2026-11-10/patch/P0_사실오류_카드.json`.
- `cardEdits` 에 없는 카드가 바뀌면 테스트가 막는다(「기존 카드가 변형되지 않는다」) — 바뀐 자식 카드 id 도 적는다.
- 과 글(「함께」)은 §4.4 의 「글 고침」대로(`gen_<ID>.py` 가 있으면 거기).
