# 그림 감사 지시서 (그림 ↔ 글 ↔ 상자)

## 무엇을 감사하는가
생물학 그림 암기 교재(Sketchy 방식)다. 「과(lesson)」 하나는 16:9 그림 한 장과 「정거장」 여러 개로 되어 있다.
정거장마다 그림 속 물건 하나(또는 몇 개)가 생물학 사실 하나를 나른다. 학습자가 정거장을 차례로 들을 때마다
그림 위에 「상자」(그 부분만 밝게 비추는 네모)가 켜져 그 물건을 가리키고, 「말」이 낭독된다.

너는 독립 감사원이다. 만든 사람의 글을 믿지 말고 **그림에서 네 눈으로 직접 본 것만** 근거로 삼는다.
생물학 내용이 맞는지는 네 일이 아니다(다른 감사원이 본다). 너는 **그림 · 글 · 상자가 서로 맞는지**만 본다.

## 파일 (과 ID 가 L38b 라면)
- 글: `AUD/pk/L38b_v.txt` — 정거장마다 「물건」(그림 속 무엇인지) · 「고리」(물건 = 뜻) · 「말」(낭독문) · 상자 이름
- 그림: `AUD/img/L38b_A.jpg` (깨끗한 전체) · `AUD/img/L38b_B.jpg` (상자 테두리와 번호를 그린 전체)
  · `AUD/img/L38b_C.jpg` 또는 `_C1.jpg` `_C2.jpg` (상자 범위 **그대로** 자른 조각 모음 — 칸 위 노란 이름표가 상자 이름)
- 상자 이름: 정거장 3의 상자가 하나면 `3`, 둘 이상이면 `3a` `3b` …
- 상자가 없는 정거장(대개 0번 = 장면 소개, 마지막 = 되짚기)은 전체 그림을 가리킨다 — 상자 검사는 건너뛴다.
- 좌표는 2048×1144 기준이다. B 그림은 1536 폭(×0.75)이다.
- AUD = /tmp/claude-0/-home-claude/adba3dea-fd2a-5075-a226-d8c1b6963879/scratchpad/audit

더 가까이 봐야 하면 python(PIL)으로 `/tmp/b2/lesson/img/<ID>.webp`(2048×1144 원본)를 잘라
`AUD/out/tmp/<묶음이름>_*.png` 로 저장해 Read 로 본다. **그 밖의 어떤 파일도 고치거나 만들지 않는다.**

## 과마다 하는 일 (과 하나를 끝내고 다음 과로)
1. `_v.txt` 를 읽는다. A · B · C 그림을 Read 로 본다.
2. 정거장마다 아래 세 가지를 본다.

### (가) 상자 — C 조각을 보고
- 그 정거장의 「물건」이 조각 안에 **온전히** 들어 있는가.
- 일부가 잘렸으면 `BOX-CUT`(어디가 얼마나). 뜻을 나르는 부분(개수를 세야 하는 것, 손에 든 것 등)이 잘렸으면 더 무겁다.
- 다른 물건이 들어 있거나 비었으면 `BOX-MISS`.
- 상자가 너무 넓어 다른 정거장의 물건이 여럿 함께 들어가 무엇을 가리키는지 모호하면 `BOX-LOOSE`
  (단, 「물건」 자체가 여러 물건의 묶음 · 구역 전체 · 비교인 정거장은 넓은 것이 맞다).
- 마지막 되짚기 정거장의 상자는 구역을 다시 훑는 것이다 — 「물건」에 이름이 나온 것이 상자 밖에 통째로 빠졌을 때만 적는다(mid 이하).
- 정거장의 「물건」이 여러 개를 말하는데 그 가운데 하나에 상자가 아예 없으면 `BOX-MISS`(low ~ mid)로 적는다.

### (나) 그림 ↔ 글 — A 그림(필요하면 원본을 잘라)을 보고
「물건」과 「말」이 그림에 대해 하는 **눈에 보이는 주장**을 하나씩 쪼개 그림과 맞춰 본다:
색 · 개수 · 좌우/위아래 위치 · 방향 · 동작 · 무엇이 무엇에 닿았는지/들었는지 · 열림/닫힘 · 크기 비교.
- 말하는 물건이 그림에 아예 없으면 `PIC-ABSENT`.
- 있으나 모습이 다르면 `PIC-MISMATCH`(글은 무엇이라 하고 그림은 무엇인지 둘 다 적는다). **개수는 반드시 직접 센다.**
- 같은 물건이 둘 이상 있어 어느 것인지 모호하거나, 물건이 다른 것으로 읽히면 `AMBIG`(무엇으로 읽히는지).
- 「말」 가운데 생물학 설명 부분(그림 묘사가 아닌 부분)은 대조 대상이 아니다.

### (다) 그림 자체 — A 그림 전체를 보고 (과마다 한 번)
- 글자 · 숫자 · 기호(화살표 · X · 물음표 같은 그림 기호는 괜찮다. 읽히는 문자 · 숫자만) → `TEXT`(어디에 무엇).
- 이음매(색이 계단지는 직선) · 잘린 물체 · 반투명 잔상 · 뜻하지 않게 두 번 그려진 물건 · 손가락/팔다리 이상 → `ARTIFACT`.

## 무게
- `high` — 학습자가 틀리게 배우거나 물건을 못 찾는다: 상자가 엉뚱한 곳 · 말하는 물건이 없음 · 사실을 나르는 개수/색/방향이 글과 반대.
- `mid` — 헷갈린다: 물건 일부가 잘림 · 부수 묘사가 다름 · 읽히는 글자 · 모호함.
- `low` — 흠: 작은 이음매 · 조금 헐거운 상자 · 눈에 안 띄는 차이.
취향 문제(더 예쁘게 · 더 크게)는 쓰지 않는다. 확신이 안 서면 원본을 잘라 다시 본 뒤에 쓴다. 지어내지 않는다.

## 결과 — 파일 하나 `AUD/out/<묶음이름>.jsonl` (한 줄에 JSON 하나, UTF-8)
발견마다:
{"lesson":"L38b","stop":3,"box":"3","kind":"BOX-CUT","sev":"mid","what":"오른 저울의 오른쪽 접시가 상자 오른쪽 끝에서 반쯤 잘린다","seen":"C 조각 3 오른쪽 끝에 붉은 조각이 반만 보인다","fix":"상자를 오른쪽으로 약 60px 넓힌다"}
- `box` 는 상자 이름(없으면 ""), `what` = 문제, `seen` = 그림에서 직접 본 것(위치 포함), `fix` = 고칠 방법(상자면 2048 기준 대략의 px, 글이면 바꿀 낱말).
과마다 마지막에 요약 한 줄(발견이 없어도 반드시):
{"lesson":"L38b","kind":"SUMMARY","stops":15,"boxes":17,"box_ok":16,"claims_checked":41,"note":"한 줄 총평"}

파일은 python 으로 쓴다(json.dumps(..., ensure_ascii=False)). 다 쓴 뒤 줄마다 json.loads 가 되는지 스스로 확인한다.
