# 2. 연결 스키마 (중요)

**지도를 손으로 고치지 않는다.** `PMAP`이 v9에서 멈춘 이유가 그거였다.

```js
// 소스 — sketchy.html DATA
{id:'s12p01', pc:['G1-31','G1-44'],        // 패널 단위 (행이 아직 안 정해진 것)
 f:[['하반신이 붉은 벽돌인 인부','벽세포 — 벽돌로 이름을 박았다', ['G1-31']],
    ...                                     //                        ↑ 행 단위 (선택)
```

```bash
npm run build     # 사실표 → index.html의 /*BUILD:START ... BUILD:END*/ 생성
npm run check     # 쓰지 않고 검사만
npm test          # 검증 스위트  (⚠ shallow clone 금지)
```

**빌드가 죽는 조건**: 없는 카드 ID · 셋째 자리가 배열 아님 · 이미지 누락 · 패널 ID 중복 · 한 행에 요소 4개.

**`links_report.md`가 태깅 검수 창구다.** sketchy.html이 15MB라 git diff를 못 읽는다.

## 큰 파일 고치는 법 — 괄호 스캐너

`sketchy.html`은 **절대 재직렬화하지 않는다**. DATA를 eval해서 다시 쓰면 서식·주석이 다 날아간다. 대신:

1. **앵커 문자열이 정확히 1번 나오는지 먼저 센다** (`assert count==1`)
2. 여러 곳을 고칠 때는 **뒤에서부터** 넣는다. 앞에서 넣으면 뒤쪽 위치가 밀린다
3. **백틱 리터럴(`bx`)에 넣을 때는 `` ` ``와 `${`가 없는지 검사한다.** v17에서 실제로 깨졌다 —
   작업자가 쓴 마크다운 `` `s18p02` ``의 백틱이 템플릿 리터럴을 닫아 **14MB DATA가 통째로 죽었다.**
   마크다운을 HTML로 바꾸고(`**x**`→`<b>`, `` `x` ``→`<code>`) 잔류를 검사한다
4. 작은따옴표 문자열(`traps`, `f`)에 넣을 때는 `'`가 없는지 검사한다. 대신 `「」`를 쓴다
5. **쓰기 전에 고친 결과를 다시 파싱해 본다.** 한 글자만 새도 DATA 전체가 죽으므로,
   재파싱에 실패하면 원본을 안 건드리고 중단한다

`607c007`에서 두 갈래가 났다. **라이브가 14커밋, 이 세션이 9커밋. 어느 쪽도 다른 쪽을 포함하지 않았다.**

라이브는 이미 110장인데 파일이 106장이라고 말하고 있었으므로 어긋남이 눈에 안 띄었다.
→ **머리말을 DATA에서 세도록 고쳤다.** 고정값은 반드시 어긋난다(§10과 같은 병).

**병합 방법** (재발 시 그대로 쓸 것):

1. 바닥은 **라이브**. 여기에 로컬의 `f` · `bx` · `br` · `pc`만 얹는다. `IMG` · `svg` · `traps`는 라이브 것
2. **사실표는 3방향 병합.** 기준↔라이브는 **LCS로 정렬**한다 — 이름 앵커가 소품명을 통째로
   갈아치우므로 문자열 유사도로는 짝이 안 잡힌다. 기준↔로컬은 **소품·사실을 이어 붙여** 비교한다 —
   앵커는 소품에 있던 말을 사실 쪽으로 옮기기도 한다
3. **연속된 del 뭉치와 그 뒤 ins 뭉치를 순서대로 짝짓는다.** 안 그러면 나란한 두 행을 고친 경우 하나만 잡힌다
4. **링크는 합집합.** 어느 쪽도 안 버린다
5. 남는 충돌은 손으로 판정하고 코드에 이유를 적어 둔다(v17은 2건)

**표보다 그림이 훨씬 더 많이 틀렸다.**

| **출제 빈도 주장인데 문항이 0건** | COP I/II의 「단골」 — 기출 1,475문항에 COP 문항 0건 |
| **널리 알려졌으나 소스에 없음** | 힐 계수·인 순환·장간막·분기도 회전. **분기도 함정의 유일한 근거는 이 프로젝트가 쓴 문서였다 — 자기 참조** |

**규칙: 함정·q블록은 출처 없이 쓰지 않는다.** 못 찾으면 「확보 기출에 없다」고 그대로 적는다.

## ★ 그림을 받으면 「몸을 센다」

`s34p01` 초안에 「알갱이 안에 사람이 **딱 둘**」이라고 썼는데 그림 속 몸은 **셋**이었다.
그림을 다시 그리지 않고 **「몸은 셋인데 세포는 둘 — 업고 업힌 한 쌍이 아직 안 갈라진 생식세포다」**로
읽는 법을 바꿨다. 그러자 시점 오류까지 같이 잡혔고, 장면 전체가 **「보이는 수 ≠ 세포 수」**로 잠겼다.

> **배포 전 자문**: ① 그림에 있는 모든 것이 사실표에 있나 ② 사실표의 모든 소품이 그림에 있나
> ③ **세라고 시킨 것을 실제로 세면 그 수가 나오나**

## 적대적 검수를 반드시 한 번 태운다

`s34p01`은 자체 검수를 통과했는데 **적대적 서브에이전트가 8건**, `s34p02`는 **10건**을 잡았다.
**기출 인용 53건 중 51건은 EXAM 색인으로 기계 대조가 된다**(문항번호 + 정답 번호). 대학명만 docx에서 본다.
**기계 검증을 먼저 돌리고 사람/에이전트는 나머지만 본다.**

## 기존 그림 수정은 「재생성」이 아니라 「편집」이다

참조 이미지를 안 붙이면 **완전히 다른 장면을 새로 그려 온다.** 현재 PNG를 **첨부**하고
`Edit the attached image. Do not redraw it.`으로 시작, **바꾸지 말 것을 명시적으로 나열**한다.

**⚠ Gemini에 파일을 붙이는 것은 자동화가 안 된다.** `<input type="file">`이 DOM에 없어 확장이 손을 못 댄다.
배포본 캡처는 해상도가 낮아 편집 기준으로 부적합하다. **사용자가 직접 붙이는 수밖에 없다.**

# 5. 제작 규칙 14개 + 심볼 사전

**전부 실패에서 역산한 것이다.**

1. **낯선 배치는 익숙한 장면으로 수렴한다** — 예외를 그리려면 정상 사례를 여럿 깔고 하나만 반대로
2. **안 시킨 소품이 들어온다** — `No extra props, no unrelated tools, no decorative clutter` 고정
3. **가로 나열 컷은 여백이 생긴다** — 지그재그·세로 왕복으로
4. **없는 것을 그리려면 명사로 지정한다 ★**
5. **개수는 못 센다** — 자리·방향·유무로 변환. **2×2는 100% 통과**, 「여덟 개」는 7개로 나온다
6. **개수가 시험 포인트가 아닌 경우가 많다** — 아니면 숫자는 HTML 라벨로
7. **참조 이미지는 구조물도 옮긴다** — 새 창에서 재시도
8. **크기·길이·넓이는 배수로 지정한다 ★**
9. **이름이 형태로 풀리면 그게 최우선 ★** — **인명 유래는 적용 불가**(파네트·브루너·쿠퍼·이토·카스파리·헨레·푸아죄유·보어·마이스너·파치니)
10. **소품 6개가 실질 상한** — 넘으면 패널을 쪼갠다. **현재 38장이 위반이다(§0의 3번)**
11. **가장 눈에 띄는 것부터 서술한다** — 프롬프트가 길면 뒤쪽 문장이 통째로 버려진다
12. **★ 개수는 「정확히 N」으로 안 나온다 — 자리 + 명시적 부재로 나온다**
    > *"Its **left** ankle is roped to a round grey stone and its **right** ankle is roped to a round grey stone. **Apart from those two ankle stones there is no stone anywhere else in the picture.**"*
    **3과 4에도 통한다** — 「왼쪽부터 첫 셋은 납작하고 문에 가장 가까운 넷째만 통통하다. 그림 어디에도 다른 꼬투리는 없다」
13. **★ 결핍·병변은 상처가 아니라 사물로 그린다** — 부은 다리로 시키면 안전 필터가 빈 응답을 준다.
    발목에 묶인 돌로 바꾸면 통과하고, **그게 Sketchy에 더 맞다 — 심볼은 상처가 아니라 물건이다**
14. **★ 작은 표식에는 물건 두 개까지다** — 셋을 넣으면 순서가 무너지거나 하나가 빠진다

**보조** — 재시도 프롬프트에 통과분도 다시 쓴다(교체 현상) · 프롬프트 안의 모순을 먼저 잡는다 · 정사각형을 명시한다

# 8. 그라운딩 규칙 (절대)

**모든 소품·사실·함정은 프로젝트 소스 파일에 대응해야 한다. 지어내면 안 된다.**

대응되지 않는 소품은 삭제한다. **대응 소품이 없는 사실 행도 표에서 뺀다.**
반대로 **그림에 있는데 표에 없는 소품은 표에 행을 추가한다.**

> ⚠️ **단, 방향을 먼저 본다 (v17 추가).** 표와 그림이 **정반대**인 경우(수가 다르다·방향이 반대다·
> 위치가 반대다)는 **표가 옳고 그림이 틀린 것**이다. 표를 그림에 맞추면 **틀린 사실을 외우게 된다.**
> 이럴 땐 표를 그대로 두고 **그림 큐로 넘긴다.** v17에서 이 유형이 184건 — DROP의 세 배였다.

새 장면 설계 전에 반드시 `project_search`로 근거를 먼저 확인한다.
**함정·숫자·q블록에는 출처(대학명·연도·문항번호)를 괄호로 남긴다.**
**근거가 없으면 「확보 기출에 없다」고 그대로 쓴다.** 있는 척하지 않는다.

> **준수 실측 (2026-08-04)**: 함정 **178/189 = 94%** · q블록 **109/110**

**소스**: Campbell 12판 변환분(ch19~46) · 기본서 16종 · 지엽 정리.docx · BM편입생물기출 상/하 ·
한의편 기출 3종(원광·동국·모의 9회)

# 10. ★ 테스트는 「그때의 사실」이 아니라 「불변식」을 적는다

이 프로젝트에서 **일곱 번** 같은 실수를 했다.
`PMAP 705` · `고아 23` · `PROW 0` · `106패널` · `파일 95개` · `장면 37개` · `G1-26이 없다`.

| 나쁜 테스트 | 좋은 테스트 |
|---|---|
| `장면 수 === 37` | `주입기가 장면·패널을 늘리거나 줄이지 않는다` (주입 전과 대조) |
| `PMAP === 705` | `PMAP ≥ baseline.json의 값` (래칫) |
| `패널 === 106` | `PTIT 키 수 === 소스 패널 수` (자기 일관성) |
| `파일 95개` | `그림 파일 수 ≥ 도해 아닌 패널 수` |
| `구조가 v12와 같다` | `v12의 패널이 전부 아직 있다` (부분집합) |
| `PTIT·PBR 키 집합 동일` | `v10b의 키를 다 갖고 있다` (부분집합) |
| `G1-26이 없다` | **`G1-26이 있다면 행 단위여야 한다`** (대응 소품 증명) |
| `CARDS 5531 무변경` | `기존 카드가 유실·변형되지 않는다` (추가는 허용) |

**`G1-26`이 좋은 사례다.** v12에서 「대응 소품 없는 오태깅」이라 뺐는데, 그 뒤 `s12p04`(비타민 조제실)가
생겨 **자리가 실제로 생겼다.** 「없어야 한다」로 박아 뒀으면 정당한 진도가 테스트를 깨뜨린다.

`test/baseline.json`을 **배포할 때마다 현재 값으로 올린다.** 내리는 건 회귀다.
**무시되는 테스트는 없느니만 못하다.**
