## 2. 제미나이 편집의 실측 법칙 — 이 세션의 가장 큰 소득

`s31p02` 10회 · `s01p05` 5회(실패) · 나머지 1~3회를 돌려 확인했다.

> **삭제와 추가는 먹는다. 이동·회전·재배치는 거의 안 먹는다.**

| 지시 유형 | 성공률 | 비고 |
|---|---|---|
| **삭제** (「지워라」) | 매우 높다 | 한 번에 3개까지 동시에 됐다 |
| **추가** (「그려 넣어라」) | 높다 | 사방 담장 추가는 1차에 바로 됐다 |
| **재질·색 변경** | 높다 | 붉은 벽돌 → 판벽 1회 |
| **형태 재작도** | 중간 | 통째로 다시 그리게 하면 됐다(부분 수정은 3회 실패) |
| **이동·회전·반전** | **거의 0** | `s01p05` 「배 하나만 반대 방향」 5회 전부 실패 |
| **개수 「exactly N」** | 낮다 | 자리로 잠그면 된다 |

**그래서 프롬프트를 이렇게 쓴다:**

- 「A를 B로 옮겨라」 → **「A를 지워라」 + 「B 자리에 새로 그려라」**
  - `s05p02` 「인물을 돌려세워라」 → 「지우고 **뒷모습**으로 새로 그려라」 → 1차 성공
  - `s04p05` 「몸을 90° 돌려라」 → 「지우고 문간에 뒷모습으로 들어가게」 → 1차 성공
- 「담장 위로 궤도를 옮겨라」 → **「궤도는 두고 담장을 궤도 위로 쌓아라」** (`s33p03`, 1차)
- 「깔때기 8개」 → **「네 마디 각각의 좌우에 하나씩」** (`s04p03`, 1차)

### 회귀가 반복된다

**고친 것이 다음 회차에 되살아난다.** `s31p02`에서 문지기 지팡이를 네 번 지웠는데 네 번 되살아났다.
→ **회차마다 검수 항목을 처음부터 전부 다시 센다.**

### 회차가 적으면 톤 드리프트도 적다

10회(`s31p02`)는 벽돌이 형제보다 **12% 어두워져** 반복 보정이 필요했고,

**통과 기준을 낮추는 것이 화질을 지키는 길이기도 하다.**

## 4. 음성 후크를 처음으로 그림에 넣었다 (`s17p03`)

| 라벨 | 소리 다리 | 그림에 넣은 것 | 산물 |

| **알**파 | **알**(달걀) → 노른자 | 레몬 초소 옆 **깨진 달걀과 노른자** | 노랑 → 레몬 = **산** |

「알파」와 「알칼리」는 소리가 겹치는데 α가 내는 것은 산이라, **후크를 안 넣으면 틀린 후크가 저절로 생긴다.**
**사실표 소품 칸도 같이 고쳤다** — 그림에만 넣고 표를 안 고치면 대조가 어긋난다.

> 인출 단서에 적용되는 규칙이 아니다. 근거는 필요 없고 **일관성만** 있으면 된다.

## 5. 패널 분할 절차 (`s16p02`에서 확립)

7행 → 4행 + 3행. **분할선은 목록이 아니라 동선이 만든다.**

1. **동선으로 가른다.** 「구부리기(cAMP)」 방 / 「쪼개기(IP₃·Ca)」 방 —
   고리는 앞방에만, 판·자갈은 뒷방에만. **심볼이 방마다 갈리는 것**이 분할의 값이다
2. **그림 두 장을 먼저 만든다.** 앞방은 옮겨갈 소품을 **삭제**, 뒷방은 앞방을 화풍 참조로 **신규 생성**
3. **카드는 본문 키워드로 분류한다.** 앞방만 18 · 뒷방만 9 · 양쪽 8(둘 다) · 키워드 없음 6(원 패널)
4. **DATA는 그림이 다 나온 뒤에 고친다.** 먼저 쪼개면 그림 없는 패널이 생긴다 —
   **빌드가 「이미지 파일 없음」으로 막아 준다**

### 테스트 하나가 틀린 것을 지키고 있었다

`verify_build.js`의 「PMAP 값이 한 건도 안 바뀜」은 고정값 테스트라 **패널 분할 자체를 금지**한다.
불변식 둘로 교체 — **「카드가 패널을 잃고 빈손이 되지 않는다」 + 「옮겨가도 같은 장면 안이다」**.

## 8. 규칙으로 굳힌 것

1. **세션 첫 명령은 `git fetch origin`이다.** 이걸 안 해서 하루를 낡은 바닥에서 썼다
