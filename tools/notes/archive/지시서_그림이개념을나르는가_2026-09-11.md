# 지시서 — 그림이 개념을 나르는가 (2026-09-11)

다음 세션(Opus 든 누구든)이 **이 파일 하나만 읽고** 그대로 실행할 수 있게 쓴다.
저장소 `BAEggman/biology2` · 사용자 성영석 · 시험 2027-01-01 (한의대·편입 생물학).

사용자의 말 그대로:
> 「블라인드 테스트 완료했는데 그림을 보면 진짜 이 소품을 보고 이 개념을 떠올릴 수 있다고?
>  의문점이 생기는 부분들이 정말 많아. 더군다나 phonetic link 도 빠진 개념들이 많고.」
> 「그림이 개념을 잘 이해하는 도구로서 쓰인다는 원래 목표에서 멀어지고 있어.」

**이 의심은 옳다.** 아래 진단은 그 이유를 증거로 적은 것이고, 절차는 그것을 고치는 순서다.

---

## 1. 문제가 무엇인가 — 진단 (증거 붙임)

### R1. 검증이 전부 글자 대조다 — 그림을 본 도구가 없다
`tools/audit_phonetics.js` `audit_loanwords.js` `audit_hookreach.js` `audit_answers.js` `test/verify_hooks.js`
전부 `sketchy.html` 의 **문자열**을 읽는다. `img/` 를 만지는 유일한 도구 `audit_srslink.js` 도 `fs.existsSync` 로 **파일이 있는지**만 본다 — 열어 보지 않는다.
그래서 소품 칸에 「루비」라고 적혀 있으면 통과다. **그림에 루비가 있는지, 학생 눈에 띄는지, 그것이 Rb 를
떠올리게 하는지는 아무 도구도 본 적이 없다.** 감사가 전부 초록인데 그림이 의심스러운 이유가 이것이다.

### R2. 블라인드 테스트가 새는 시험이었다
`tools/blind/brief/b32_s1.md` 를 보라. 1단계(차가운 훑기)가 **단원명과 판 제목**을 준다.
2단계는 **개념 이름 목록 + 덱 공통 약속표 전체**를 준다.
→ 「seen=Y」는 「제목과 약속표를 쥐고 보니 찾겠다」이지 「소품을 보고 개념이 떠올랐다」가 아니다.
192판 전수 결과(`outputs/블라인드테스트_2026-09-10.md`)는 **인식(recognition) 점수**이지 **인출(recall)** 점수가 아니다.
채점자 스스로 「제목이 흘렸다」「약속표 덕」이라고 적은 행이 여럿이다.

### R3. 소품 칸이 그림을 따라갔다
그림이 사양대로 안 나오면 **사양을 그림에 맞춰 고쳤다** (s31p02 · s31p04 · s21p02 — 세션 32부에서 자백).
그러면 글과 그림은 일치하고 감사(R1)는 통과하지만, 소품은 더 이상 **사실을 담는 물건**이 아니라
**그림 설명문**이 된다. 「초록인데 의심스러운」 상태를 만드는 정확한 기전이다.

### R4. 「없다」를 「빈 자리」로 그렸다 — 딱지
빈 동전판 · 빈 연장 걸이 · 빈 스코프 받침대 (2026-09-10~11).
「여기 없다」는 물건은 **사실을 나르지 못한다** — 학생은 「빈 판 = ATP 없음」을 따로 외워야 한다.
스케치의 소품은 인과·소리·모양·수 중 하나로 사실에 **닿아야** 한다. 없음은 사실 칸이 진다.
(33부에서 셋을 「기계」로 바꿨다: 양동이→담장 아치+물레방아 · 양동이→기계 아가리+선반 동전 둘 · X 자 판자.)

### R5. 편집 위에 편집
같은 판을 세 번씩 편집(s37p01 · s11p05 · s21p02). 회차마다 화풍이 밀리고 **이웃 소품이 깨진다.**
실물 증거: s11p05 는 어제 편집이 **사람 등의 쇠 띠(RNA 주형)를 기둥의 코일로** 옮겨 5행 후크를 죽였다.
원본에서 다시 시작하자 저절로 복구됐다. → 글에는 있는데 그림에 없는 행(F1)은 이렇게 생긴다.

### R6. 음차 후크 감사의 범위가 좁다 — 그리고 면제가 후크보다 많다
`audit_loanwords.js` 는 **카드의 답**에 든 이름만 본다. 사실표에는 있는데 묻는 카드가 없는 이름은 안 본다.
`audit_hookreach.js`: 후크 316건 중 **「묻는 카드가 없음」60건 · 「진짜 눈먼 자리」22장**.
`hooks.json`: 후크 **316** vs 면제·오탐 **404** (답면제 71 · 외래어면제 218 · 인명면제 16 · 음차오탐 94 · 인명오탐 5).
면제 하나하나에 이유는 적혀 있고 대체로 조리가 있다(확인함). 그러나 **「학생이 이미 안다」는 전부 내 판단**이고
사용자에게 한 번도 검증받지 않았다. 사용자가 「빠진 개념이 많다」고 하면 그 판단이 틀린 자리가 있다는 뜻이다.
⚠ 오르니틴·시트룰린·알로락토오스·니트로게나아제·파이토크롬 같은 것이 「이미 아는 낱말」로 면제돼 있다 — 재심 대상.

### R7. 후크 사전 ↔ 그림의 이음매를 아무도 안 본다
`verify_hooks.js` 는 hooks.json 의 props 낱말이 **소품 칸 문자열**에 있는지만 본다(R1 과 같은 병).
「루비」가 소품 칸에 있어도 그림 속 루비가 콩알만 하거나 다른 붉은 것과 섞이면 후크는 죽은 것이다.

### R8. 검수자가 나 자신이다
사양을 쓰고 · 제미나이에 시키고 · 결과를 판정하고 · 통과시키는 감사를 짜는 것이 **전부 같은 나**다.
「이 소품이면 떠오른다」는 판단은 답을 이미 아는 사람의 판단이다. 처음 보는 눈이 한 번도 안 들어왔다.
(블라인드 테스트가 그 시도였는데 R2 로 샜다.)

### R9. 지표를 좇았다
블라인드의 seen=N 개수를 줄이는 쪽으로 움직였다(64행 목록을 카드 수로 정렬해 위부터). 사용자가 짚었다.
seen=N 행 중 상당수는 **사실 칸이 져야 할 「없음」 사실**이라 seen=N 이 옳은 상태였다.

### R10. 회수 절차 버그
`~/Downloads` 에 같은 이름이 있으면 크롬이 「이름 (1).png」로 저장하는데 옛 파일을 결과로 읽었다.
멀쩡한 생성을 두 번 「실패」로 판정하고 근거 없는 교훈(「부정문이 소환장」)까지 만들었다. 정정함.
→ 이름에 `Date.now()` 를 붙이고 `mtimeMs` 를 확인한다 (`tools/fetch_gemini.md` 2026-09-11(2) 절).

**한 줄 요약**: 글은 서로 일치하고 감사는 초록인데, **그림이 사실을 나르는지는 아무도 본 적이 없다.**
그리고 본 적이 없는 채로 그림을 여러 번 덧칠했다.

## 2. 「끝났다」의 정의 — 행 하나의 게이트

행 하나가 끝난 것은 아래 넷을 **처음 보는 눈(별도 에이전트)** 이 그림을 열고 확인했을 때다.

| 게이트 | 묻는 것 | 실패 이름 |
|---|---|---|
| G1 있다 | 소품 칸이 말하는 물건이 그림에 또렷이 있고 **수가 맞다** | F1 |
| G2 닿는다 | 그 물건에서 짧은사실로 가는 **고리를 한 마디로 말할 수 있다** (소리/모양/구조/수/자리) | F2 |
| G3 안 부딪힌다 | 같은 물건이 딴 판에서 딴 뜻이 아니고, 그림이 사실과 반대가 아니다 | F3 |
| G4 소리 | 짧은사실에 임의의 이름이 있으면 그 소리를 붙잡는 물건이 **그림에** 있다 | 음차없음 |

판정 기준 전문: `tools/vision/RUBRIC.md`. 그 기준으로만 판정한다. **후하게 주지 않는다.**

## 3. 실행 절차

### 0. 복구
```
cd /tmp && rm -rf b2 && git clone --depth 50 https://github.com/BAEggman/biology2.git b2 && cd b2
git log --oneline -3      # 이 지시서를 넣은 커밋이 보여야 한다
python3 tools/vision/make_batches.py     # 묶음 32개(6판씩) 다시 생성 — 그림 경로는 저장소 안
```
push 는 컨테이너 프록시가 403 이다(읽기는 됨). 배포는 번들 + `push_b2.sh`(§6).

### 1. 그림 감사 — 192판 전수, 처음 보는 눈으로
**운용 규칙 (2026-09-11 에 8개 동시 → 주간 한도 초과로 전부 죽었다. 반복하지 마라)**
- 한 번에 **에이전트 3개 이하**, 에이전트당 **묶음 하나(6판)**.
- 에이전트는 판 하나 끝낼 때마다 `tools/vision/out/<pid>.txt` 에 **즉시 쓴다**. 끊겨도 쓴 판은 산다.
- 한 파도(wave)가 끝나면 `ls tools/vision/out | wc -l` 로 진도를 보고 다음 파도를 띄운다.
- 에이전트에게 **판 제목·단원명·약속표를 주지 않는다.** 묶음 파일에 일부러 없다. 주면 R2 를 되풀이한다.

에이전트에게 주는 프롬프트(그대로):
```
생물 Sketchy 덱의 그림 감사다. 먼저 tools/vision/RUBRIC.md 를 Read 로 읽어라.
그다음 tools/vision/batches/bNN.md 를 읽어라. 판 6개와 각 판의 소품·짧은사실이 있다.
판마다 Read 로 그림(경로가 적혀 있다)을 실제로 열어 보고, 작은 것은 zoom 해서 세고,
행 하나하나를 RUBRIC 기준으로 판정해라. 판 하나를 끝낼 때마다 그 판의 판정 줄들을
tools/vision/out/<pid>.txt 에 Write 로 즉시 써라. 마지막 답은 「끝 — <쓴 pid 목록>」만.
```
(NN 을 바꿔 가며. 이미 `out/` 에 있는 판은 건너뛰어도 된다.)

### 2. 집계 → 큐
```
python3 tools/vision/collect.py      # outputs/그림감사_<날짜>.md + tools/vision/verdicts.json
```
큐의 순서는 **F1(글이 거짓말) → F2(딱지) → 음차없음 → F3**, 각 안에서 **카드 수 내림차순**.
⚠ 카드 0장인 행은 큐 뒤로 — 시험에 안 나온다고 덱이 판단한 행이다(스케치도 그렇게 자른다).
⚠ F2 중 「없음을 그린 것」은 소품을 지우고 **사실 칸이 지게** 하는 것이 답일 수 있다. 그림을 늘리지 마라.

### 3. 수리 — 한 판에 한 번, 원본에서
행 하나를 고치는 순서. **순서를 바꾸지 마라.**
1. **사양 먼저.** 소품 칸을 고쳐 쓴다 — 사실을 **인과·소리·모양·수** 중 하나로 나르는 **물건**으로.
   수가 있으면 수를 적는다(「못 셋」). 덱 약속표(`hooks.json _심볼예약` · s32 사실표 등)와 부딪히지 않는지 grep 으로 본다.
   새 약속을 만들지 않는다. (예: 「막혔다」= X 자 판자, 31-4 와 같은 뜻)
2. **원본을 꺼낸다.** `git log --oneline -- img/<pid>.webp` 로 마지막 편집 전 커밋을 찾아
   `git show <그 커밋>^:img/<pid>.webp` 를 png 로 만들어 올린다. **오늘 편집본 위에 편집하지 않는다.**
3. **프롬프트.** 명령문으로 연다. 바꿀 것 **하나**(같은 자리의 두세 요소는 하나로 친다).
   「Count them as you draw: one, two, three. No fourth.」식으로 수를 박는다.
   지켜야 할 것은 **하나하나 이름을 불러** 나열한다. 화풍·팔레트·시점 유지. 글자 없음.
   프롬프트 전문을 `tools/prompts/<pid>_<요지>_vN.txt` 에 남긴다.
4. **회수.** `a.download = '<pid>_' + Date.now() + '.png'` · 스테이징 응답의 **mtimeMs 가 방금인지** 확인.
   절차 전문: `tools/fetch_gemini.md` (모델은 Pro Extended — 사용자 지시).
5. **판정.** 결과를 Read 로 열고 G1~G4 를 **행마다** 적는다. 하나라도 실패면 **사양을 고치지 말고** 3 으로 돌아간다.
   두 번 실패하면 그 행은 `_후크대기` 에 이유와 함께 적고 넘어간다 — 세 번째 덧칠은 하지 않는다.
6. **설치.** `(247,241,224)` 합성 → 너비 1024 → WEBP q92 m6 → `img/<pid>.webp` + `tools/blind/png/<pid>.png`.
   `tools/blind/manifest.json` 의 그 행 prop/fact/label 을 소품 칸과 **같게** 맞춘다. `node build.js`. `node test/all.js`.
7. **재검.** 고친 판만 묶음으로 만들어 §1 의 에이전트에게 **다시** 준다(그린 사람이 판정하지 않는다).

### 4. 음차 후크 — 범위를 넓히고 면제를 재심한다
1. 그림 감사의 `음차없음` 열이 1차 목록이다(카드 답이 아니라 **사실표 전체**에서 나온 것).
2. `hooks.json` 의 `_외래어면제`(218) · `_답면제`(71) · `_인명면제`(16) 를 **사용자에게 보여 주고** 고른다 —
   「이건 내가 이미 안다 / 이건 외워야 한다」. 내 판단으로 면제를 늘리지 않는다. 사용자 판단만 면제가 된다.
3. 후크가 필요한 이름마다 §3 의 순서로 **물건**을 넣는다. 후크의 형태는 `hooks.json _형태` 를 따른다(① 소리 ② 글자 모양).
   `_심볼예약` 과 부딪히면 안 된다. 한 판에서 같은 물건이 두 이름을 나르지 않는다.
4. `node tools/audit_hookreach.js` 의 「진짜 눈먼 자리 22장」과 「일부만 닿음 14건」은 **카드 연결** 문제다 —
   `tools/link_cards.py` 쪽에서 판을 걸어 준다. 그림을 새로 그릴 일이 아니다.

### 5. 블라인드 테스트를 다시 짠다 (선택 — 그림 감사가 끝난 뒤)
1단계 브리프에서 **단원명·판 제목을 뺀다.** 2단계에서 **약속표를 빼고** 개념 이름 목록에
**같은 단원 다른 판의 개념 3개를 섞어**(디스트랙터) 준다. 디스트랙터를 물건에 붙이면 F2 다.
`tools/blind/make_brief.js` 의 해당 줄을 고친 뒤에만 다시 돌린다. 그 전 결과는 인식 점수로만 쓴다.

### 6. 배포
```
git bundle create /tmp/b2_<날짜>.bundle origin/main..main
```
번들 + `push_b2.sh` 를 `~/Downloads` 에 넣고 사용자에게 `bash ~/Downloads/push_b2.sh` 한 줄을 부탁한다.
스크립트에 토큰을 넣지 않는다(`grep -c github_pat push_b2.sh` = 0). 커밋 서명은 세션 안내대로.
