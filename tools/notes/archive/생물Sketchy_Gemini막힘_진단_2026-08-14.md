# Gemini가 응답을 안 뱉는다 — 진단 기록 (2026-08-14)

s39p03(14:07경)까지는 정상이었고 **그 직후부터 이 계정의 모든 응답이 죽었다.**
사용자가 확장 프로그램 권한을 다시 준 뒤에도 같았다.

그러니 프롬프트도, 구도도, 모델도, 전송 경로도 원인이 아니다.

## ★ 결정적 증거 — 서버는 200을 준다

`read_network_requests`로 잡은 실제 요청:

```
POST .../assistant.lamda.BardFrontendService/StreamGenerate?...  → statusCode 200
POST .../batchexecute?rpcids=ESY5D ...                           → statusCode 200
```

**인증(401/403)도, 한도(429)도, 서버 오류(5xx)도 아니다.** 요청은 받아들여지고 200이 온다.
그런데 화면에는 아무것도 안 그려진다.

DOM을 뜯어 보면 응답 컨테이너가 계속 대기 상태에 멈춰 있다:

```
thinking-overlay.enable-luminous-fast-follows
structured-content-container.model-response-text.has-thoughts
  p.pending / span.pending      ← 여기서 안 움직인다
```

정지 버튼(「대답 생성 중지」)도 안 사라져서 **다음 전송이 막힌다.**
정지를 눌러 「대답이 중지되었습니다」가 떠도 버튼이 남아 있어, 탭을 새로고침해야 작성란이 산다.

## 새 대화 화면은 전송 자체가 안 된다

`/app`(새 채팅)에서는 보내기 버튼을 눌러도 **글자가 작성란에 그대로 남고 대화가 안 만들어진다**
(`user-query` 0개, URL이 대화 주소로 안 바뀜). 기존 대화에서는 전송은 되는데 렌더가 안 된다.

→ 스트리밍 렌더링 쪽 문제로 보인다. 이쪽에서 고칠 수 있는 게 없다.
