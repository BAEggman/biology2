#### 2. 틀렸을 때 그림을 자동으로 펼친다

지금 `picLink`는 **링크일 뿐이라 안 누르면 안 본다.** 그런데 그림이 가장 필요한 순간은 틀린 직후다.

```js
// applyGrade 안
if(grade<=1 && PMAP[id]) showPanelInline(PMAP[id]);   // 🔴 아는 줄 알았는데 / ❌ 그냥 틀림
```

**전제 — 이미지를 쪼개야 한다.** `index.html`은 지금 `<img>` 태그가 **0개**다(이미지를 렌더한 적이 없다).
2.68MB짜리 학습 앱에 13.88MB를 내장하면 모바일에서 못 쓴다. 대신:

```
img/s31p01.webp … 95개 · <img loading="lazy">
```

실측: WebP 원본 합계 10.16MB / 95장 — **평균 109KB · 최대 192KB · 90퍼센타일 152KB.**
(base64로 부풀어 13.88MB가 된 것이지 이미지 자체는 가볍다.)

틀린 카드에서만 1장 로드. 평소 트래픽 증가 0.

> 비용: 이미지 분리 스크립트 + 106파일 push + 코드 5줄 · 효과: **방법론적으로 가장 큰 한 방.**

#### 4. 연결을 카드가 아니라 **사실표에 건다**

지금 스키마는 `카드ID → 패널ID` 1:1이다. 제안 1에서 봤듯 벌써 깨진다.
방향을 뒤집는 게 구조적으로 옳다:

```js
// sketchy.html의 f 배열
f: [
  ['하반신이 붉은 벽돌인 인부', '벽세포 — 벽돌로 이름을 박았다', ['G1-31','G1-44']],
  …                                                        // ↑ 카드 ID 배열 추가
]
// PMAP은 빌드 시 여기서 역산해 생성
```

이게 나은 이유 넷:

- **입도가 맞는다.** 1행 = 1사실 = 카드 1~3장. 패널(사실 5~7개) 단위보다 정확하다
- **1:N도 N:1도 표현된다.** S-PL-14 같은 걸친 카드가 자연스럽게 들어간다
- **그라운딩 규칙(§11)과 같은 축이다.** 사실표에 근거가 없는 카드는 애초에 그림과 무관하다는 뜻 — 태깅 안 하는 게 정답이라는 판정이 자동으로 나온다
- **사실표 검증과 태깅이 한 작업이 된다.** v12에서 이미 590행을 한 행씩 대조했다. 그 작업에 카드 ID만 얹으면 된다

> 비용: 스키마 변경 + 빌드 스크립트 · 효과: **앞으로의 태깅 단가를 절반으로 낮춘다.** 지금 하면 3·5·6이 전부 쉬워진다

#### 5. 사실표 590행 → 카드 후보 반자동 제시

순수 자동 매칭은 안 된다. 실제로 돌려봤다 — 용어 기반 매칭은 **2.8%**밖에 안 걸리고, 챕터 기반은 68% 걸리지만 **입도가 파탄**이다(s16 「전화국」 2패널에 345장이 걸린다).

대신 **후보 제시 + 사람 승인**은 된다.

```
[s12p01 · 벽세포 = 벽돌 인부]
  후보 ① G1-31  위샘 세포 3종과 분비물은?          [O] [X]
  후보 ② G1-44  내인자의 기능과 흡수 부위는?        [O] [X]
  후보 ③ X-G-12 악성빈혈의 기전은?                  [O] [X]
```

하루 100행이면 6일. **판정은 넘기지 않는다** — §10의 원칙 그대로, 기계가 고르고 사람이 승인한다.

> 비용: 매칭 스크립트는 내가 짬 · 사용자는 O/X만 · 효과: 590행 전체를 6일에

### ★ B급 — 방법론을 완성한다

#### 6. 역방향 — 그림에서 그 카드만 복습 시작

지금은 **카드 → 그림** 단방향이다. 그런데 Sketchy의 실제 학습 순서는 반대다: 그림을 먼저 외우고, 카드로 확인한다.

`sketchy.html`의 각 패널에 버튼 하나:

```
[이 그림 카드 12장 복습 →]  →  index.html?panel=s31p01
```

이게 있어야 **「그림을 공부했다」가 복습 사건이 된다.** 지금은 그림을 아무리 봐도 SRS에 아무 기록이 안 남는다.

> 비용: 중간 · 효과: 제안 4를 먼저 하면 거의 공짜로 따라온다

---

#### 7. 신규 도입만 패널 단위로 묶는다 (복습은 계속 섞는다)

Sketchy의 학습 단위는 카드가 아니라 sketch 한 장이다. 같은 패널의 카드를 신규 도입 때 몰아주면 **한 번의 그림 인출로 여러 카드를 부호화**한다. `weave()`·`interleave()`가 이미 있으니 붙일 자리가 있다.

**반론을 같이 적어둔다.** 학습과학에서는 블록형(몰기)보다 인터리빙이 장기 파지에 낫다고 본다. 몰아주면 단기 체감만 오르고 시험장에서 무너질 수 있다.

**절충이 정답이다 — 도입만 묶고 복습은 섞는다.** 초기 부호화에는 맥락이 붙어야 하고, 인출 연습은 섞여야 한다. 이 둘은 충돌하지 않는다.

> 비용: 낮음 · 효과: 중간 · **먼저 소규모로 한 게이트만 시험해볼 것**
