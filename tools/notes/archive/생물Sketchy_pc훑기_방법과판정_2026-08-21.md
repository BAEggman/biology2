# pc 훑기란 무엇인가 — 방법과 판정 기준 (2026-08-21)

`sketchy.html` 의 판 하나는 이렇게 생겼다.

```js
{id:'d01p03', t:'광합성 Z 도식',
 pc:["A0-107","C0-10","C0-100", … 38장],          ← 판 단위
 f:[["전자의 출발점", "물의 광분해 → O₂ 발생", ["C0-13","C0-99", …]],   ← 행 단위
    ["최종 전자수용체", "NADP⁺",              ["C0-146#1","C0-117"]]]}
```

## 두 가지 걸기

| | 뜻 | 앱에서 |
|---|---|---|
| **행 링크** (`f` 의 셋째 칸) | 「**이 소품이 이 사실을 나른다**」 — 증거가 있다 | 복구 화면이 `PROW` 를 읽어 **그 행을 강조**한다 |
| **pc** (판 단위) | 「이 판 **어딘가에** 있다」 — 어느 행인지 안 적혀 있다 | 강조할 행이 없어 **사실표 전체가 밋밋하게** 뜬다 |

**pc 가 나쁜 진짜 이유는 강조가 아니라 검증을 건너뛴다는 것이다.**
행에 걸 때는 「그 소품이 정말 그 급소를 그리나」를 사람이 한 번 본다.
pc 는 그 확인 없이 뭉텅이로 얹은 것이라 **급소가 그림에 아예 없는 카드도 섞여 있다.**

> ★★ 가장 또렷한 증거 — `H0-124`(교질삼투압).
> `d03p02` 의 bx 에는 이미 「**표에서 내린 것 (그림에 대응 소품이 없다)**」라고
> 지난 세션 사람이 판정해 적어 두었는데, **pc 에는 그대로 남아 있었다.**

## ★★★ pc 는 다른 것도 가린다

### ① 다른 감사를 가린다
음성 후크 감사는 **행**을 센다. pc 카드는 행이 없으니 안 잡힌다.
오늘 pc 318장을 행으로 내리자 음성 후크 미달이 **52 → 95장**이 됐는데,
**위반 행은 74 → 71 로, 패널은 42 → 40 으로 줄었다.**
새 위반이 생긴 것이 아니라 **가려져 있던 카드가 드러난 것**이다.
진짜 밀린 양은 처음부터 95장쯤이었고 pc 가 그중 절반을 숨기고 있었다.

### ② 검사의 앵커가 되어 있기도 하다
`verify_build.js` 의 음성 테스트 「없는 카드 ID 를 넣으면 빌드가 죽는다」가
`s12p01` 의 **pc 목록**에 `ZZ-NOPE-9` 를 끼우는 방식이었다.
그 판의 pc 가 0이 되자 치환이 아무 일도 안 해서 「다른 이유로 죽음」이 됐다.
> **검사해야 하는 불변식은 「없는 카드 ID면 빌드가 죽는다」이지 pc 라는 자료 구조가 아니다.**
그 판의 **첫 행 카드 배열**에 끼우도록 고쳤다 — pc 가 다 사라져도 살아남는 앵커다.

## 다섯 판정

| | 판정 | 언제 | 오늘 |
|---|---|---|---|
| ① | **행으로 내림** | 급소가 그 행에 그려져 있다 | 232장 |
| ② | **중복 제거** | 이미 다른 판 행에 제대로 걸려 있다 | 1장 |
| ③ | **폐기** | 급소가 그림에 **아예 없다** | 52장 |
| ④ | **그림 고침 → 새 행** | 그릴 만한데 안 그려졌다 | 18개 행(35장) |
| ⑤ | **배열 · 이사** | 급소가 두 판에 나뉘었거나 엉뚱한 판에 얹혔다 | 30장 |

### ①과 ③을 가르는 한 줄
> ① 카드의 **급소가 그림에 있고** 세부는 행의 글이 보탠다
> ③ **급소 자체가 그림에 없다**

### ★ 판정은 판의 종류를 탄다
**도해는 Gemini 왕복 없이 직접 고칠 수 있다.** 그래서 그림 판이었으면 ③ 폐기였을 것이
도해에서는 **④ 그림 고침**이 된다 — `d01p03` 루멘 확대 칸(5장) · `d02p03` 정자 꼬리(3장).
**그림 판의 ④ 는 Gemini 재생성**이고 소품 6개 상한에 이미 닿은 판이 많아(`s16p01` 은 아홉)
그림 판에서는 ③ 이 살아 있는 판정이다.

### ★★ ③ 폐기의 진짜 모양은 「덱에 그 그림이 없다」다
한 판에 없는 것과 **덱 전체에 없는 것**은 다르다. 훑기의 절반은 이 확인이다.

| 없는 것 | 카드 | 되살릴 조건 |
|---|---|---|
| 시상하부 방출호르몬 (TRH·CRH·GnRH) | 6장 | **방출호르몬 판을 세우면** |
| 초기 원위세뇨관 (NCC·PTH·Ca²⁺) | 5장 | **초기 원위 판을 세우면** |
| 심장 구조 (1심방1심실 …) | 4장 | **심장 구조 판을 세우면** |
| 유사분열 5단계 (전중기) | 2장 | **유사분열 단계 판을 세우면** |
| 칼시토닌 | 2장 | `s07p03` 에 하나만 그려 넣으면 |
| 촉각 수용체 넷의 깊이 순서 | 1장 | `s27p01` 에서 넷을 한 줄로 세우면 |
| **덱 전체 0건인 낱말** — `Ras` · `구아닐산 고리화효소` · `탈인산화효소` · `과립세포` · `NCC` · `활면` · `무기호흡` · `수용체 단백질 돌연변이` | 8장 | 그 개념을 그리면 |

### ★ pc 는 「엉뚱한 판에 얹힌 것」을 못 잡는다
「이 판 어딘가에」만 말하므로 아예 다른 판에 그려진 카드가 얹혀 있어도 티가 안 난다.
**행으로 내리려고 한 장씩 보아야 드러난다.**

| 카드 | 얹혀 있던 판 | 실제로 그린 판 |
|---|---|---|
| `C1-48`·`C1-49`·`D0-144` 비분리 | d01p01 | **d05p08** 「정상 배우자 0개 / 2개」 |
| `C1-45` 제1난모세포 정지 | d01p01 | **d02p03** 「1차 정지 = 전기(복사기)」 |
| `B0-102` 아데닐산 고리화효소 | s16p01 | **s16p02** 「곧은 막대가 고리가 되는 기계」 |
| `X-SG-18` 로돕신·빛 | s16p01 | **s15p02** 「지붕의 접시 안테나」 |
| `X-SG-14` 니코틴성/무스카린성 | s16p01 | **s23p02** 「슬롯이 문에 직접 달린 창구」 |
| `Q0-25#2` 전엽 TSH | s07p03 | **s07p02** 「나비 모양 접시」 |
| `G1-39` B12 = 코발라민 (② 중복) | s12p01 | **s12p04** 「코가 코발트빛 파란 사람」 |

### ★ 배열이어야 할 것이 pc 로 눌려 있었다
「둘·셋을 비교하라」는 카드는 급소가 여러 판에 나뉜다. 한 판에만 걸면 답의 절반을 버린다.

| 카드 | 어디에 나뉘어 있나 |
|---|---|
| `B0-96` 2차 전달자 다섯 | s16p02(cAMP) · s16p02b(IP₃·DAG·Ca²⁺) · s15p02(cGMP) — **세 판** |
| `G0-183` 근육 셋의 칼슘 기전 | s08p01 용접 쇠막대 · s08p02 튀는 물방울 · s08p03 조수 — **세 판** |
| `S-PL-15` 개화 광주기 3원칙 | s20p02 모래시계·손전등 · s20p03 양면 토글 |
| `L0-3` 세포벽 성분 | s05p01 갑각 질감 벽 · s28p01 네 배 두꺼운 벽 |
| `S-EV-5` 균류 5군 | s05p01 개울가 3채 · s05p02 주머니와 갈퀴 |
| `S-AN-8` 순환계로 문 나누기 | s04p02 선충 · s04p03 연체·환형 |
| `X-PL-2`·`S-PL-2` 배낭 vs 화분립 | s34p01 · s34p02 |

### ★ 크기가 판정을 바꾼다
| pc 크기 | 폐기 비율 |
|---|---|
| 41장짜리(`s16p01`) | 6장 폐기 (15%) |
| 1장짜리 22판 | **3장 폐기 (14%)이지만 18장은 그냥 행으로 내려갔다** |

**1장짜리 pc 는 「어디 걸지 몰라 얹은 것」이 아니라 「한 장이라 미뤄 둔 것」이었다.**
판당 판정 하나라 값도 가장 싸다 — 이런 것부터 훑는 것이 옳다.

## 도구

### `tools/pc_sweep.py` — 판정표를 받아 한 번에 옮긴다
```python
from pc_sweep import sweep
sweep('d02p03',
  DEMOTE=[('["최종 산물"', ['D0-143','Q1-11'])],        # ① 같은 판의 행으로
  MOVE  =[('d05p08', '["★ ② 칸 배우자 넷"', ['C1-48'])], # ⑤ 다른 판의 행으로
  NEWROW=[('소품', '사실', ['카드'])],                    # ④ 그림엔 있는데 행이 없던 것
  DROP  =['C1-5'])                                       # ③ 폐기
```
pc 목록과 판정표가 **정확히 같은 집합**인지 먼저 확인하고, 아니면 죽는다.
같은 카드를 `DEMOTE` 와 `MOVE` 에 다 쓰면 **배열**이 된다.

### `tools/pcbatch.js` — 여러 판을 한꺼번에 펼친다
`node tools/pcbatch.js 1 1` → pc 가 1장인 판 전부를 행·pc카드 Q/A 까지 한 번에 보여 준다.
판정은 이 출력만 보고 내릴 수 있다.

### ⚠ 바늘 함정 여섯 (전부 실측으로 물렸다)
1. **소품 이름이 다른 행의 사실 칸에도 나온다** → 행 여는 `[` 부터: `'["최종 산물"'`
2. **부분 문자열** — 「순환적 경로」는 「비**순환적 경로**」 안에 통째로 들어 있다
3. **원래부터 한 카드가 두 행에 걸친 판**이 있다 → 중복 검사는 「이번에 얹은 것」만 잡는다
4. **pc 를 먼저 지우고** 행에 걸어야 한다 — 안 그러면 중복 검사가 pc 목록을 보고 잘못 걸린다
5. **소품에 `<b>` 태그가 박혀 있으면 태그째** 써야 한다: `'★ <b>개울 한가운데</b> 물속에'`
6. **행을 작은따옴표로 쓴 판이 있다**(`s34p05`·`s34p06`) — 파서가 여는 따옴표를 보고 맞춰야 한다

### `tools/sync_svg.py` · 도해 검수
`tools/_<pid>.svg` 가 원본이고 `sketchy.html` 에 인라인 사본이 있다 — 한쪽만 고치면 배포본이 어긋난다.
컨테이너에 한글 글꼴이 92개 있는데 `cairosvg` 가 기본 sans-serif 로 그려서 도해를 눈으로 못 봤다:
```python
svg = src.replace('<svg ', '<svg font-family="NanumGothic" ', 1)
```
**좌표만 보고는 겹침을 못 잡는다.** `text-anchor="middle"` 안의 `<tspan>` 은 겹쳐 그려지니 한 색으로 쓴다.
