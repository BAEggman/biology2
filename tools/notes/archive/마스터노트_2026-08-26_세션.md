## ★★★★ 오늘의 가장 큰 것 — execCommand 로 넣은 글도 보내진다

2026-08-25 에 「**친 글만 보내진다**」고 결론 내렸던 것이 **절반만 맞았다.**
오늘 s04p04 v2(3,031자)·v3(1,864자)를 둘 다 `document.execCommand('insertText')` 로 넣고
`computer action=key "Return"` 으로 보냈고 **둘 다 정상으로 접수됐다**(대화 `b72b319122ca478f`).

| 넣는 방법 | 보내는 방법 | 결과 |
|---|---|---|
| `execCommand('insertText')` | **송신 단추 클릭** | ❌ 조용히 실패 (옛 기록) |
| `execCommand('insertText')` | **`key "Return"`** | ✅ **보내진다** |
| `computer type` | 아무거나 | ✅ 보내진다 (느리다) |

갈리는 것은 **넣는 방법이 아니라 보내는 방법**이었다. Quill 은 `beforeinput`/`input` 을 듣고
있어서 execCommand 로 들어온 글이 제 모델에 정상으로 앉는다. 그 모델을 읽는 것은 **키보드
처리기**이고, 송신 단추는 다른(앵귤러 쪽) 상태를 읽는 듯하다.

### 새 절차 — 골칫거리 셋이 한꺼번에 없어졌다

```js
const bin=atob(B64); const b=new Uint8Array(bin.length);
for(let i=0;i<bin.length;i++)b[i]=bin.charCodeAt(i);
const TXT=new TextDecoder('utf-8').decode(b).trim();
const ed=document.querySelector('.ql-editor'); ed.focus();
const sel=getSelection(), r=document.createRange();
r.selectNodeContents(ed); sel.removeAllRanges(); sel.addRange(r);
document.execCommand('insertText',false,TXT);
return JSON.stringify({want:TXT.length, got:ed.innerText.trim().length,
                       match:ed.innerText.trim()===TXT});   // ← 반드시 검증
```
그 다음 `computer action=key "Return"` 한 번.

1. **좌표를 안 쓴다** — 컴포저가 363↔388↔391 로 움직여도 상관없다.
   8-25 에 프롬프트 넷을 통째로 날린 사고가 이 좌표 어긋남이었다.
2. **CDP 30초 시간 초과가 없다** — 3,000자가 한 호출에 즉시 들어간다.
3. **쪼개 치다 반쪽이 보내지는 사고가 없다** — 통째로 갈아 끼운다.
4. 덤으로 **`hidden` 탭에서도 `key "Return"` 이 먹었다**(오늘 두 번 다).
   프롬프트는 base64 로 실어 보내면 따옴표·유니코드 이스케이프 걱정이 없다.

⚠ 길이 검증(`match:true`)은 **여전히 반드시 한다.** 모델 알약(Pro + 확장된 사고) 확인도 그대로다.
자세한 것은 `tools/fetch_gemini.md` 의 「2026-08-26(1)」 절.
