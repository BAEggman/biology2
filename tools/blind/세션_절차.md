# 그릴 때마다 블라인드 1세션 — 「복원이 되는가」 (2026-10-13 신설)

> 사용자 지시(그대로): 「매번 그릴 때마다 블라인드테스트를 1세션 실행해보고 복원이 되는지 검증도 해보자」
> → 판을 새로 그리거나 고칠 때마다, 그 판에 대해 **처음 보는 판독자** 둘이 그림에서 사실표를 **복원**하는지 잰다.
> 못 복원한 행은 고치고(그림 또는 글), **고친 뒤 새 판독자로 다시 잰다**. 같은 판독자에게 다시 보이면 기억이 섞인다.

## 왜 README 의 3단계와 다른가
- 예전 1단계는 **단원명 · 판 제목**을 줬다 → cold 가 제목 덕을 봤다(지시서 2026-09-11 R2).
  여기서는 **그림만** 준다. 판 표제어를 그림에서 읽어 내는지가 통합판의 목적(한 단원이 한 장에서 한눈에)이기 때문이다.
- 단계를 셋으로 나눠 **실제 학생의 순서**를 흉내 낸다:
  1. **생판**(그림만) → `cold` — 처음 보는 사람에게도 읽히는가
  2. **덱 약속표**(`reservations.md`)를 준 뒤 → `warm` — 덱을 배우고 온 학생이 이 판에서 사실을 **복원**하는가 ← **합격 잣대**
  3. **개념 이름 목록**(섞어서)을 준 뒤 → `cued` — 이름을 들으면 그림에서 되찾는가(Sketchy 가 실제로 기대는 것)
- 채점자는 따로(Opus). 「약속표 덕」「이름 목록이 흘림」「배경지식으로 맞힘」을 note 에 밝힌다.

## 합격 기준
- 판 표제어 1순위 = 그 판(단원)의 주제 — 1·2단계 둘 다
- 구역(통합판)마다 표제어가 맞는다
- **사실 복원 warm ≥ 90%** (틀 행 제외 · 판독자 둘 각각) — cued 는 참고로 함께 적는다
- 두 판독자가 **다 못한 행**(warm ≠ Y)은 반드시 고친다. 한 사람만 못한 행은 note 를 읽고 판단한다.

## 하는 법
```
python3 tools/blind/setup_session.py <pid> <batch> <작업폴더>      # 그림 · 약속표 · 섞은 이름 목록 · 프롬프트 넷을 작업폴더에
```
1. 판독자 A · B — `Agent(general-purpose, model=sonnet)` 둘을 **동시에** `prompt_stage1_A.txt` · `_B.txt` 로.
2. 둘 다 끝나면 `SendMessage` 로 `prompt_stage2.txt`(폴더 이름만 A/B 로) → 끝나면 `prompt_stage3.txt`.
3. 채점자 — `Agent(general-purpose, model=opus)` 에 `prompt_grader.txt`.
   결과: `tools/blind/out/<pid>.json`(A, 표준 꼴 — report.js 가 읽는다) · `<pid>.B.json` · `<pid>.통합판독.json`.
4. 끝나면 판독자 답과 채점을 `tools/blind/out/<pid>_판독/<batch>/` 로 옮겨 남긴다(다음 재검이 out/ 를 덮으므로).
5. 고칠 자리 → 고침 → **새 묶음 번호로** 1부터 다시(판독자는 새로 띄운다).
