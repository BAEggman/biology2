# Gemini 결과를 「기기 다리 없이」 받는 법 (2026-11-13 · L53b 에서 씀)

기기 다리(remote-devices)가 5xx 로 죽으면 `~/Downloads` 에 내려받은 PNG 를 가져올 수 없다. Chrome 확장은 따로 살아 있으므로 화면 갈무리로 **원본 화소를 그대로** 받는다.

1. 결과가 뜬 Gemini 탭에서 `window.__show(0)` — 가장 최근 그림을 화면 왼쪽 위에 **기기 픽셀 1 : 1**(CSS 너비 = 원본 너비 ÷ devicePixelRatio · `image-rendering: pixelated`)로 검은 바탕 위에 띄운다. `$SP/helpers2.js` 에 `__show` · `__hide` 가 들어 있다.
2. Chrome 도구 `computer` 의 `zoom` 을 `save_to_disk: true` 로(⚠ `scale` 을 주면 저장 파일도 줄어든다 — 주지 말 것). 영역은 스크린샷 좌표(1419 × 840 틀)로, 기기 픽셀 ÷ 2.3674(= dpr 2.2 × 1527 / 1419)보다 조금 크게:
   - 1024 × 572(바탕) → `[0, 0, 440, 250]` 한 번 · 1024 × 683(3 : 2) → `[0, 0, 440, 295]` 한 번
   - 683 × 1024(2 : 3) → `[0, 0, 295, 230]` + `[0, 210, 295, 440]` 두 번(한 번에 높이 870 px 쯤을 넘기면 줄여 저장된다)
3. 저장 경로(`/tmp/claude-chrome-screenshots-*/…png` — 컨테이너 안)를 `capstitch.py <out> <W> <H> <조각1> <y1> [<조각2> <y2>]` 로 이으면 원본과 같은 크기의 PNG. 겹친 줄을 맞춰 어긋남을 찾고(err 0.0 이어야 한다) 오른쪽 · 아래 검은 여백이 0 인지 찍어 준다.
4. 끝나면 `window.__hide()`.

확인: 검은 여백이 정확히 0 · 경계가 한 화소에 끊김 → 무손실. 물빛 (117, 187, 233) 이 L53a 원본 PNG 와 같았다.

다리가 돌아온 뒤 `~/Downloads` 의 내려받은 파일(이름은 .png 이지만 속은 WEBP)과 견줌: 넷 모두 크기 같음 · 화소 차 최대 2 ~ 3 · 평균 0.2 ~ 0.4 — 갈무리가 내려받기와 사실상 같다.
